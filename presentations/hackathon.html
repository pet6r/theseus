A binary is a maze. The agent isn't the hero — it's the thread.

The SOC reverse-engineering bottleneck

  • Alert volume: a mid-sized SOC sees 100s of "suspicious binary" tickets per day. EDR flags ≠ verdict.
  • Manual RE is slow: a competent analyst burns 30–120 min per unknown sample to reach a confidence level worth escalating.
  • Most binaries are boring: signed installers, in-house tools, false-positive heuristic hits. The analyst's expensive time is wasted on triage.
  • Output is inconsistent: free-form notes in ticket comments, no shared structure, hard to feed back into SOAR.

What if static triage of unknown binaries cost cents per sample instead of hours per sample?

Theseus in 30 seconds

Input

A single binary. PE, ELF, Mach-O, kernel driver.

Pipeline

Four sequential phases, each one tool-using Claude against a live Ghidra SQL surface.

Output

report.json (schema-stable) + reveal.js deck + optional SOAR webhook push.

Time

~3 min for calc.exe. ~10–20 min for a real malware sample.

Each phase ends in strict JSON. capability and ioc both see triage; verdict sees all three. orchestrator._extract_json recovers the largest JSON object/array from the model's output.

One tool. Massive surface.

The agent gets exactly one tool: ghidrasql_query(sql). That's it. No filesystem, no shell, no decompiler RPC, no network.

But the SQL surface is wide enough to do real RE work:

CategoryTables / views
Functionsfuncs, function_locals, callers, callees, callgraph_edges
Codeinstructions, blocks, cfg_edges, loops, switch_tables
Referencesxrefs, call_edges, string_refs
Symbolsimports, exports, strings, equates
Decompilerpseudocode, decomp_lvars, decomp_tokens
Memory / Typesmemory_blocks, types, type_members

The agent writes its own SQL. It can also annotate (UPDATE funcs SET name = …) but Theseus deliberately keeps it read-mostly.

Each request narrows the labyrinth. No row, no claim. The thread is auditable — every step in report.json traces back to a SQL response.

Why the thread keeps it honest

Free-form LLM RE invents function names, fabricates addresses, paraphrases decompilation that never existed. Theseus is structurally resistant — the agent cannot answer questions whose evidence isn't already in the database.

Hallucination classWhy it can't happen here
Inventing a function name funcs is populated by Ghidra's analyzer from the actual binary. SELECT * FROM funcs WHERE name = 'fake_fn' returns 0 rows. Empty result → agent must revise.
Fabricating an address Every address cited in the report has to come from a row Ghidra returned. There is no other source — the model has no access to the bytes directly.
Paraphrasing decompilation pseudocode is Ghidra's decompiler output for the exact function — verbatim C-like code, not a paraphrase. Agent quotes; doesn't summarize from memory.
Wrong xrefs / call graph xrefs and callgraph_edges are computed by Ghidra. Agent reads them; can't synthesize them.
Imaginary imports / strings imports + strings are byte-extracted from the PE/ELF. Agent queries; the binary is the source of truth.

The system prompt enforces it: "Every claim must cite an address, function, import, or string from the database. Never speculate without grounding." The relational schema makes that rule mechanically checkable, not just aspirational.

Code: backend abstraction

# src/theseus/backends/base.py
class LLMBackend(Protocol):
    def run_phase(
        self,
        *,
        system: str,
        user_prompt: str,
        phase_name: str,
        max_turns: int,
        log: Callable[[str], None],
        on_token: Callable[[int, int], None] | None = None,
        on_progress: Callable[[str, float], None] | None = None,
    ) -> PhaseResult: ...


def get_backend(name, *, ghidrasql_url, libghidra_url, model) -> LLMBackend:
    name = (name or os.environ.get("THESEUS_BACKEND") or "anthropic").lower()
    if name == "anthropic":
        return AnthropicBackend(ghidrasql_url=..., model=model)
    if name in ("claude_code", "claude-code", "cc"):
        return ClaudeCodeBackend(ghidrasql_url=..., model=model)
    raise ValueError(f"unknown THESEUS_BACKEND: {name!r}")

Adding an open-source local backend = drop a file in backends/ + one line in get_backend.

Code: in-process MCP tool (claude_code backend)

# src/theseus/backends/claude_code.py (excerpt)
@tool(
    "ghidrasql_query",
    "Execute SQL against the ghidrasql HTTP server. Use LIMIT.",
    {"sql": str},
)
async def ghidrasql_query(args):
    sql = args["sql"].strip()
    async with httpx.AsyncClient(timeout=60.0) as c:
        resp = await c.post(
            f"{ghidrasql_url}/query",
            content=sql.encode("utf-8"),
            headers={"Content-Type": "text/plain"},
        )
        return {"content": [{"type": "text", "text": resp.text}]}

server = create_sdk_mcp_server(name="ghidrasql", version="1.0.0",
                               tools=[ghidrasql_query])

options = ClaudeAgentOptions(
    system_prompt=system,
    mcp_servers={"ghidrasql": server},
    allowed_tools=["mcp__ghidrasql__ghidrasql_query"],
    max_turns=max_turns,
    model=self.model,
)
async for message in query(prompt=user_prompt, options=options): ...

Pain points — things that bit me

  • Port collisions: ghidrasql's default RPC port is 18080 — same as the LibGhidraHost GUI. find_free_port + --rpc-port override fixed it.
  • Protobuf vs JSON: libghidra/rpc is binary protobuf, not JSON. Dropped the libghidra_decompile tool entirely — agent uses ghidrasql's pseudocode table instead.
  • Raw-SQL body: POST /query wants Content-Type: text/plain with raw SQL, not {"sql": …}. Cost me an evening.
  • cp1252 codec death: redirecting stdout on Windows breaks Rich's box-drawing chars. Force PYTHONIOENCODING=utf-8 + sys.stdout.reconfigure at CLI entry.
  • SDK hard-fails on max_turns: Anthropic SDK degrades gracefully, Claude Agent SDK raises. Wrapped in try/except and use partial output.
  • Drag-and-drop: DearPyGui has none. Win32 WM_DROPFILES + WndProc subclass via ctypes — and remember to pin argtypes on x64 or HDROP overflows c_int.

The agent is a thread, not a hero. It guides — it doesn't decide.

Verdict taxonomy

The schema's verdict.label enum collapses RE outcomes into 5 buckets:

CLEAN   benign, signed, no offensive primitives. soc_action: ignore

SUSPICIOUS   weak signals, packed, anti-debug. enrich / monitor

VULNERABLE   BYOVD / dual-use — exposes ring0 R/W primitives. quarantine + escalate

MALICIOUS   performs C2, exfil, injection, destructive action. quarantine / escalate

UNKNOWN   analysis incomplete (packed, no symbols, agent gave up). escalate to human

Adding vulnerable was a hackathon-day insight — a poorly-written signed driver isn't malicious, but a BYOVD weapon on a corporate endpoint is still an incident.

Takeaways

Theseus is one project. The shift it sits on top of is bigger.

⏱ Cost curve collapsed

Static RE went from 1–2 hours of senior analyst time to cents and minutes. Capability not new — price is.

🔓 Obscurity is dead

Stripping, packing, "security through obscurity" already lost to manual RE. They lose faster now. Protect logic structurally: server-side checks, attestation, enclaves.

📜 IP risk widens

Algorithms, license checks, undocumented protocols, file formats — all cheaper to recover. Legal "no reverse engineering" clauses don't stop the capability; they only matter after.

🛡 Defenders gain too

Supply-chain vuln research, SOC-scale malware triage, BYOVD detection, IR campaign correlation — all benefit from the same cost drop.

⚖ "Can it" → "May it"

Technical barriers gave way to legal and ethical ones. Sandboxing, authorization, audit trails, clear scope — the new gating layer.

🌐 Open-source as equalizer

If competitors can read your binary cheaply, open-sourcing non-core parts costs less than it used to. The trade math just shifted.

Theseus is built for defenders. The technique is dual-use — that's true of every advance in RE since the disassembler.
